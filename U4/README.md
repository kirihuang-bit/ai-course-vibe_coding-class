## 兩件容易搞混的事：Skill 和 MCP

這堂會同時出現這兩個字，它們**不是同一種東西**：

| | 它是什麼 | 比喻 |
|---|---|---|
| **Skill / 指令** | 把**你的話**存起來，之後打 `/名字` 就重播一次 | **貼在牆上的工作守則**——省得你每次重講 |
| **MCP** | 讓 AI 能操作**它原本碰不到的東西** | **給它多一隻手**——原本它只能讀檔案，現在能開瀏覽器 |

> **一個是省你的力氣，一個是擴充它的能力。**
>
> Skill 沒有讓 AI 變強，只是讓你不用一直複製貼上同一段話。
> MCP 才是真的讓它能做到之前做不到的事——**所以 MCP 要問權限，Skill 不用。**

## 三台 MCP 各解決什麼問題

| MCP | 原本的問題 | 裝了之後 |
|---|---|---|
| **Chrome DevTools** | AI 看不到畫面，你說「跑起來怪怪的」它只能猜 | 它自己開 `localhost` 看 console、Network，還能截圖 |
| **Context7** | AI 的知識有時間點，講的可能是舊版寫法 | 查最新官方文件，**答案要能說出來源** |
| **Codebase Memory** | 專案一大，它得一個檔一個檔翻 | 建立專案地圖，回答得出「改這裡會影響哪裡」 |

前兩台的設定**專案裡已經寫好了**（根目錄的 `.mcp.json`）——用 Claude Code 打開這個資料夾時，它會問你要不要啟用。第三台要另外裝。

### ⚠️ MCP 權限三問

裝任何 MCP 之前都先問：

1. **它能讀到什麼？**
2. **它能不能寫入？**
3. **會不會碰到正式資料或 token？**

> 這三問不是這堂課的形式。**你以後在公司裝任何工具都該問一次。**
> 一個能讀你整個硬碟、又能連外網的工具，跟一個只能看 `localhost` 的工具，
> 風險差很多。

## 裝不起來怎麼辦：先講清楚保底

MCP 是這堂最容易卡住的地方——它牽涉到你電腦的環境、網路、權限，
**33 個人的電腦不會都一樣**。

> **裝不起來不影響過關。**

| 裝不起來的 MCP | 保底做法 | 一樣算完成 |
|---|---|---|
| Chrome DevTools | 自己按 F12 看 console，手動截圖 | ✅ |
| Context7 | 自己去查官方文件，把網址貼進報告 | ✅ |
| Codebase Memory | 直接問 AI，但**要求它回答時引用具體檔名** | ✅ |

**驗收看的是「你有沒有拿到那個結果」，不是「你有沒有裝成功那個工具」。**

卡超過 10 分鐘就切保底方案，繼續往下走。**今天最重要的產出是那篇技術紀錄，不是 MCP。**

## 今天的重頭戲其實是那篇文章

STEP-03 和 STEP-04 會佔掉今天大半時間。要寫的不是心得，是**技術紀錄**：

```text
主題：我如何用 AI coding agent 接手並交付一個 GYOZA WOOD 鍋貼店控制台系統
```

**你不用從空白頁開始。** `blog-lab/src/content/blog/gyoza-wood-case.md` 已經是一份**骨架**，
八節，每一節都有三行提示：**要回答什麼**、**證據在哪**、**可以怎麼開頭**。
你讀提示、寫自己的內容、再把提示刪掉。

判斷標準只有一條：

> ### **每一段至少要有一個「別人可以拿去查證」的東西。**
> 檔名、數字、指令的輸出、一張截圖——四種任一種都算。**一段都沒有，那一段就是空的。**

`STEP-03` 裡有**五組「空泛版 vs 有證據版」**的對照，教你怎麼分辨。

> 這篇文章的讀者是**可能要雇用你的人**。他要看的不是你會不會用 AI，
> 是你**知不知道自己做了什麼、怎麼確認它是對的**。
>
> 骨架裡的**第 5 節**特別重要——那一節寫的是**你在 U3 自己發現的那個限制**。
> 其他七節每個人都寫得出來，只有那一節是你在現場才知道的事。

**截圖你在 U2、U3 應該已經收了五張**（存在 `blog-lab/public/images/`）。
今天只需要再補三張，都是當天會做到的事。

## C4 要學會的技術力

- **Skill / 指令**：說得出它是「把重複的話存成 SOP」，不是讓 AI 變聰明
- **MCP**：說得出它是「讓 AI 操作它原本碰不到的東西」
- **權限三問**：能讀什麼、能不能寫、會不會碰正式資料
- **保底思維**：工具裝不起來時，說得出「我要的結果是什麼、還有什麼方法拿到」
- **要求出處**：AI 引用文件時，會追問「這是哪來的」
- **技術寫作**：每個主張都附證據，不寫空泛心得
- **部署**：說得出 repo 上傳 ≠ 部署（U1 埋的伏筆，今天收）
- **公開前檢查**：文章裡不能有 token、個資、沒授權的圖
