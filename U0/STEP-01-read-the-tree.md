# U0 · STEP 01 ｜ 三條規則，把一萬多個檔案縮成十幾個

> **這一步完成物**：你打開檔案樹，能一眼分出「哪些要看、哪些不用看」，而且說得出理由。

## 1. 先把專案打開

你拿到的會是一個 zip：

```text
ai-project-foundation-kit.zip
```

解壓縮，得到一個資料夾：

```text
ai-project-foundation-kit/
```

用 VS Code 打開它：

```text
File → Open Folder → ai-project-foundation-kit
```

**要開最外層那一層**，不要開 `Downloads`，也不要點進去只開 `web-lab/`。

左邊的檔案樹應該長這樣（順序可能不同）：

```text
.github/
.claude/
.agents/
U0/  U1/  U2/  U3/  U4/
blog-lab/
data-lab/
line-lab/
ops-agent-lab/
prompts/
skill/
web-lab/
.gitignore
.mcp.json
AGENTS.md
CLAUDE.md
README.md
START-HERE.md
start-m11.bat
start-m11.command
```

**如果你只看到 `src/`、`index.html`、`package.json`**，代表你開到 `web-lab/` 裡面了，
請重新 Open Folder。

## 2. 先講一個數字

這個專案裡，**老師實際寫出來的檔案只有一百多個**。

但等你在 U1 跑完啟動指令之後，光是 `web-lab/node_modules/` 這一個資料夾裡面
就會有**一萬多個檔案**。

> **所以第一件要學的事不是「每個檔案是什麼」，是「哪些根本不用看」。**

接下來三條規則，每一條都會刪掉一大塊。跑完這三條，你要看的東西只剩十幾個。

---

## 3. 規則 1｜名字開頭是 `.` 的，是給工具看的

**判斷法：看它跟哪個工具同名。**

| 你看到 | 它是誰的 | 你要做什麼 |
|---|---|---|
| `.git/` | **Git 本人**。你之後所有的存檔點都存在裡面 | **絕對不要打開、不要刪** |
| `.github/` | GitHub。U4 的自動化流程放這裡 | 現在不用看 |
| `.claude/` | Claude Code。這門課的 `/debug`、`/commit-msg` 從這裡來 | U4 才會用到 |
| `.agents/` | AI coding agent 的通用設定 | 現在不用看 |
| `.gitignore` | Git 的「這些不要管」清單 | **規則 2 會打開它** |
| `.mcp.json` | MCP 設定 | U4 才會用到 |

> `.git/` 資料夾可能在你的檔案樹裡看不到——VS Code 預設會把它藏起來。
> 看不到是正常的，它一直都在。

**帶得走的一句話：**

> **以後打開任何專案，名字開頭是點的，一律先跳過。**
> 它們不是寫給你看的，是某個程式自己要用的東西。

---

## 4. 規則 2｜「自動長出來的」不用看，也不要改

**判斷法：它不是人一個一個寫的，是跑一行指令跑出來的。刪掉再跑一次就會回來。**

這條規則有一個現成的證據，就在你眼前：

> **現在去檔案樹裡找 `web-lab/node_modules/`。**
>
> - **找不到？** 很正常。它要等你在 U1 跑過 `npm install` 才會長出來。
> - **找得到？** 代表老師先幫你裝好了。
>
> 一個資料夾可以「跑一行指令就自己出現」——**這就是它不用你管的意思。**
> 你不需要看懂它，弄壞了也只要再跑一次指令就會回來。

這份專案裡，自動長出來的有：

| 資料夾 | 誰產生的 | 裡面是什麼 |
|---|---|---|
| `node_modules/` | `npm install` | 從網路下載的、別人寫好的現成程式 |
| `dist/` | `npm run build` | 打包好、準備給別人看的成品 |
| `__pycache__/` | Python 跑過之後 | Python 自己的暫存 |
| `node_modules/.vite/` | 開發伺服器 | Vite 的快取，加快啟動速度 |

### 怎麼知道哪些是自動長出來的：打開 `.gitignore`

在 VS Code 點開根目錄的 `.gitignore`，最上面六行是：

```text
node_modules/
dist/
__pycache__/
*.pyc
.DS_Store
.env
```

（底下還有幾行，是這門課的工具產物，現在不用管。）

`.gitignore` 就是一張清單，寫著「**這些東西不要放進 Git**」。
會被寫進去，通常是三種理由之一：

| 理由 | 例子 | 為什麼 |
|---|---|---|
| **自動下載的** | `node_modules/` | 每個人自己跑指令下載就好，不用跟著專案傳來傳去 |
| **自動產生的** | `dist/`、`__pycache__/` | 隨時可以重新產生，存起來只是浪費 |
| **不能外流的** | **`.env`** | **裡面有密碼** |

> **前兩種是「不用進 Git」，第三種是「絕對不能進 Git」。**
> 這是完全不同的兩件事，STEP-02 會完整講。

### 現在做一件事

> 你剛剛在 `.gitignore` 裡看到 `.env` 這一行。
> **現在回檔案樹裡找 `.env`——你會找不到它。**
> 你只找得到 `line-lab/.env.example`（多了 `.example`）。
>
> **`.gitignore` 上的東西，你的檔案樹裡可能根本不存在。**
>
> 為什麼會有一個檔案是「刻意不給你的」？為什麼要留一個 `.example` 版本給你？
> **STEP-02 會回答。**

## 5. 規則 3｜全大寫的 `.md` ＝「請先讀我」

剩下的檔案裡，有四個名字是**全大寫**的：

```text
README.md      START-HERE.md      AGENTS.md      CLAUDE.md
```

工程師的慣例是：**檔名全大寫，代表「這是給人讀的說明，請先看」。**

其中 **`README`（讀我）是全世界通用的**：

> **進到任何一個陌生的資料夾，第一件事就是找 `README.md`。**
> 它會告訴你這一層是幹嘛的。

驗證一下——這份專案有 **5 個** `README.md`，各自說明自己那一層：

| 位置 | 說明什麼 |
|---|---|
| `README.md`（根目錄） | 整包專案 |
| `U0/README.md` | 你正在上的這一堂 |
| `U1/README.md` | U1 這堂課的順序 |
| `blog-lab/README.md` | 部落格那一塊 |
| `ops-agent-lab/README.md` | Python 巡檢那一塊 |

**這條規則之所以重要**，是因為它是你唯一的「求救出口」：
看不懂某個資料夾的時候，先進去找它的 README，而不是隨便點開檔案硬看。

## 6. 結算一下

三條規則跑完：

```text
一萬多個檔案
  ├─ 規則 1 刪掉：所有點開頭的        （工具的，不是給你的）
  ├─ 規則 2 刪掉：node_modules / dist （自動長出來的）
  └─ 規則 3 標出：4 個大寫 .md        （先讀我）

剩下要看的：十幾個資料夾和檔案
```

**這三條規則不是這份專案專用的。** 換到任何一個別人寫的專案，
你都可以用同樣三步把它縮小到可以入手的大小。

看懂剩下那十幾個名字在說什麼。
