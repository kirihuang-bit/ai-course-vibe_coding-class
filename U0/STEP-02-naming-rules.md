# U0 · STEP 02 ｜ 工程師怎麼取名字

> **這一步完成物**：看到一個沒見過的檔名或副檔名，你有辦法猜它是幹嘛的，而且知道去哪裡查。

STEP-01 幫你把檔案樹縮小了。這一步要看懂**剩下那些名字**。

先講一個前提：**這些命名沒有標準答案，是工程師之間「約定成俗」的習慣。**
但正因為是習慣，所以到處都一樣——**學會了就到處通用**。

---

## 1. 兩種名字：全世界通用的，和這個專案自己取的

這是最有用的一條分類，因為它決定你**卡住的時候該去哪裡找答案**。

**判斷法：**

> **這個名字，有沒有對應到某個工具、或某個公認的東西？**
>
> - **有** → 這是**規定**，全世界都一樣，**改了工具就找不到**
> - **沒有** → 這是**人取的標籤**，只有這個專案自己知道意思

| | 例子 | 你卡住時可以怎麼辦 |
|---|---|---|
| **全世界通用** | `package.json`、`README.md`、`src/`、`public/`、`node_modules/`、`.github/workflows/` | **直接上網查**。答案全世界一樣，查得到 |
| **這個專案自己取的** | `web-lab/`、`blog-lab/`、`data-lab/`、`line-lab/`、`ops-agent-lab/`、`U1/`–`U4/`、`prompts/` | 查不到。**只能讀這個專案的 README** |

> `-lab` 是這份教材自己取的字，意思是「這一塊的練習場」。
> 換一個專案就不會有 `-lab` 了。
>
> 但「**有些名字是規定、有些是人取的**」這件事，到哪裡都成立。
> 這也是為什麼 STEP-01 規則 3 要你「先找 README」——
> **自訂名字的答案只有專案自己知道，它就寫在 README 裡。**

---

## 2. 檔名裡的關鍵字

工程師會把用途直接寫進檔名。看到這些字，先這樣猜：

| 看到 | 通常代表 | 這份專案裡的例子 |
|---|---|---|
| `config` | **設定**。改它會影響整個工具怎麼跑 | `vite.config.js`、`astro.config.mjs` |
| `ignore` | **忽略清單**：「這些不要管」 | `.gitignore` |
| `example` / `sample` / `template` | **範本，不是真的那個** | `.env.example`、`inventory_sample.csv`、`report_template.json` |
| `lock` | **鎖住版本**。機器產生的，不要手改 | `package-lock.json` |
| `src` | source ＝ **人寫的原始碼** | `web-lab/src/` |
| `public` / `static` | **直接對外公開**的檔案 | `web-lab/public/`（U1 放照片就是這裡） |
| `frontend` / `client` | 使用者**看得到**的畫面那一半 | 這份專案把它叫做 `web-lab/` |
| `backend` / `server` / `api` | 使用者**看不到**、在背後跑的那一半 | U3 會遇到 `Local backend` |

> **`frontend` 和 `backend` 是最常見的一組。**
> 一個網站通常分兩半：**前端**是你在瀏覽器裡看到、點得到的畫面；
> **後端**是在背後幫你算資料、存資料、跟外面的服務講話的部分。
>
> 這份專案沒有直接用這兩個字當資料夾名，但這一刀確實存在：
> `web-lab/` 是前端，而 U3 你會看到有一段「後端」負責去打 LINE——
> **因為密碼不能放在瀏覽器裡。** 為什麼不能，下一節就講。

## 3. `.env`：為什麼有一個檔案是刻意不給你的

STEP-01 最後留了一個問題：`.gitignore` 裡有 `.env`，但你在檔案樹裡找不到它，
只找得到 `line-lab/.env.example`。

這一節回答為什麼。**這是整個 U0 唯一值得單獨拿出來講的檔案**，
因為它同時用到前面每一條規則，也是這門課「安全」這條線的起點。

### ① 這個名字怎麼讀

`env` ＝ **environment（環境）**。

而且注意：**它沒有副檔名。** 整個名字就是 `.env`，跟 `.gitignore` 一樣。
點開頭 → 回到 STEP-01 規則 1：**它是給程式看的，不是給人讀的。**

### ② 為什麼要把東西抽出來放進它

同一份程式碼，會跑在**很多台不同的電腦上**：老師的、你的、隔壁同學的、
以後公司的伺服器。

但是——**每個人的帳號、密碼、金鑰都不一樣。**

如果把密碼直接寫死在程式碼裡，那每換一個人就要改一次程式碼，換一百個人改一百次。

所以做法是：

> **把「每台電腦都不一樣的東西」抽出來，放進 `.env`。**
> **程式碼裡只寫「去 `.env` 拿」，不寫值本身。**

這樣程式碼可以**一模一樣地**發給所有人，每個人只要準備自己的 `.env` 就好。
你手上這包和老師手上那包，程式碼是同一份——差別只在 `.env`。

### ③ 為什麼「絕對不能」進 Git

因為 Git 的工作，就是**把每一個版本永久記下來**。

> **密碼一旦被 commit、又 push 上 GitHub，之後你把它刪掉也沒有用——
> 它還留在歷史紀錄裡，任何人都翻得出來。**

而 GitHub 上的專案預設是**公開**的。

這不是嚇你的理論。外流的金鑰被別人撿去用，產生的費用和責任會算在申請它的人頭上。
現實中每天都有人這樣中招。

所以 `.env` 從第一天就被寫進 `.gitignore`——
**目的是讓你連「不小心 commit 進去」都做不到。**

> 這也是為什麼上一節說「密碼不能放在瀏覽器裡」。
> 前端的東西任何人按 F12 都看得到；密碼只能待在後端讀得到、別人看不到的地方。
> U3 會完整走一次這條界線。

### ④ 那別人怎麼知道要填什麼 → `.env.example`

如果 `.env` 不進 Git，新來的人拿到專案，怎麼知道要準備哪些東西？

**這就是 `line-lab/.env.example` 存在的理由：只留欄位名稱，不留真正的值。**

打開它看看，裡面是三個欄位：

```text
LINE_CHANNEL_ACCESS_TOKEN=請填入你的 channel access token
LINE_TARGET_ID=請填入 userId 或 groupId
LINE_REAL_SEND=0
```

等號右邊寫的是「請填入你的…」，**不是真的 token**。
它在告訴你「你需要準備這三樣東西」，但沒有洩漏任何一樣。

**標準做法**（U3 會真的做一次）：

```text
.env.example  ──複製一份、改名成──▶  .env  ──填進自己的值
     │                                  │
留在 Git 裡，給所有人看               只活在你自己的電腦上，不上傳
```

### ⑤ 帶得走的判斷法

這一節真正要你學會的不是 `.env` 這個檔名，是這個問句：

> **這個檔案裡，有沒有「只有我才有」的東西？**
> **有 → 它就不該進 Git。**

密碼、金鑰、個人帳號、公司內部資料，全部算。

以後你在任何專案看到 `.env`、`secrets`、`credentials`、`.key` 這類名字，
**第一反應應該是「這裡面有不能外流的東西」**，而不是「這是什麼，打開看看」。

> 順帶把 `example` / `sample` / `template` 這組收掉：
> **看到這三個字，就是「照著它做一份自己的」——那個檔案本身不是真的那個。**
> 這份專案裡 `inventory_sample.csv` 和 `report_template.json` 也是同樣的意思。

## 4. 副檔名 ＝ 這個檔案是給誰讀的

不用背。抓大方向就好：

| 給誰 | 副檔名 | 是什麼 |
|---|---|---|
| **給人讀** | `.md` | 說明文件。這份專案六成的檔案都是它，因為它是教材 |
| | `.csv` | 表格存成純文字，Excel 打得開 |
| **給程式讀** | `.json`、`.yml` | 設定和資料 |
| **是程式本身** | `.js`、`.jsx`、`.py`、`.ts`、`.mjs`、`.astro` | 會被執行的東西 |
| **給畫面用** | `.html` 骨架、`.css` 外觀、`.svg` 圖 | 網頁的三個部分 |
| **雙擊就跑** | `.bat`（Windows）、`.command`（macOS） | 一串指令的捷徑，例如 `start-m11.bat` |

現在你可以回答一開始那個問題了：
**為什麼這包裡 `.md` 特別多？** 因為它是教材——那些 `.md` 大部分就是你要讀的講義。

### ⚠️ 一個很容易搞混的地方

> **`.bin` 和 `.vite` 不是副檔名，是資料夾名字。**
>
> **判斷法：看點的前面有沒有東西。**
>
> | | 點前面 | 所以 |
> |---|---|---|
> | `data.js` | 有 `data` | `.js` 是**副檔名** |
> | `.vite` | 什麼都沒有 | **整個就是它的名字** |
>
> `.vite`、`.bin`（在 `node_modules/` 裡）點前面都是空的，
> 所以它們回到 STEP-01 規則 1：**點開頭 ＝ 工具的，不用看。**
>
> 同樣的道理，**`.gitignore` 也沒有副檔名**，它整個名字就叫 `.gitignore`。

### 看到不認識的副檔名怎麼辦

1. **看它在哪個資料夾** —— 位置會告訴你它大概是幹嘛的
2. **打開看前三行** —— 大部分檔案開頭就會透露自己是什麼
3. **再問 AI**

> **順序不要顛倒。** 先自己猜一遍再問，你才會累積判斷力；
> 一開始就問，你得到的是答案，不是能力。
>
> 這門課從頭到尾都是這個立場：**AI 是拿來驗證你的判斷的，不是拿來代替你判斷的。**
