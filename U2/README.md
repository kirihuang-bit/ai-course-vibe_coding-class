# U2 ｜ AGENTS.md、CLAUDE.md、Plan Mode：讓 AI 改 code，但不失控

> **這堂你不會自己寫程式，但你要負責決定 AI 能改什麼、不能改什麼，以及它改完算不算數。**

U1 你改的是一個字，改壞了自己看得出來。
**U2 開始由 AI 動手改邏輯——它改得比你快，也錯得比你不容易發現。**
所以這堂真正的功課不是「怎麼叫 AI 寫」，是**怎麼在放行之前擋下不該過的東西**。

## 這堂的骨架：四個角色

整堂課就是這四步，**你是第二步**：

| 步驟 | 誰做 | 做什麼 | 用哪張卡 |
|---|---|---|---|
| 1. **planner** | AI | 先讀專案，**只回計畫，不准改檔** | 卡 1 |
| 2. **人審** | **你** | 檢查計畫有沒有越界，**決定放不放行** | 四題檢查（見下） |
| 3. **implementer** | AI | 照核准的計畫動手改 | 卡 2 |
| 4. **reviewer** | AI ＋ **你** | 檢查改出來的東西，回 PASS / BLOCK | 卡 3 |

> **為什麼要拆成四步、不能叫 AI 一次做完？**
>
> 因為**改完再發現越界，就已經來不及了**。
> 讓它先講「我打算改什麼」，你在它動手**之前**就能喊停——
> 這時候喊停的成本是零，改完才喊停的成本是回頭清理。
>
> 這就是 U1 最後講的 PR（「請你先看過再併進去」）的同一個道理，
> 只是這次被審的對象是 AI。

### 人審那四題

放行 implementer 之前，你要對著 AI 的計畫問自己：

1. 它只打算改**允許檔案**嗎？
2. 它有沒有要**新增套件**？
3. 它有沒有要動 **`package.json`**？
4. 它有沒有想**順便重構**？

**四題都安全才放行。** 只要有一題不對，回去要求它縮小範圍，不要自己動手幫它修。

## 今天允許改的檔案

```text
web-lab/src/shopLogic.js      ← 今天幾乎只會改這一個
web-lab/src/ShopConsole.jsx   ← 需要時才動
web-lab/src/styles.css        ← 只准改備料控制台相關的樣式
```

**如果 AI 想改這三個以外的檔案，先停下來。**
它可能有好理由，但那個理由要由**你**判斷，不是由它自己放行。

## 今天要補的那個洞

打開 `web-lab/src/shopLogic.js`，第 72 行附近：

```js
// C2-HOLE: 課堂要在這裡新增第三條規則。
```

`C2-HOLE` 是老師**故意留白的地方**。你不是從零寫一個後台，
而是在一個**已經跑得動的系統裡補一條規則**——這也是你以後接手真實專案的常態。

任務是：如果現在有「LINE OA 通路、而且還沒取餐」的訂單，
備料控制台的 action queue 就要多顯示一條提醒。

> **最重要的一條驗收標準：那個數字必須是「算出來的」。**
> AI 如果直接寫「目前有 3 筆」，即使畫面看起來完全正確，**也不合格**——
> 因為資料一變它就錯了。它必須從 `orderItems` 篩出來。

## C2 要學會的技術力

- **AGENTS.md / CLAUDE.md**：專案給 AI 的工作守則，AI 動手前應該先讀
- **Plan Mode**：讓 AI 只規劃、不動手的模式
- **四角色工作流**：planner → 人審 → implementer → reviewer
- **範圍控制**：說得出「允許檔案清單」是什麼、為什麼要有
- **看得出假資料**：分得出「從 `orderItems` 算出來」和「手寫一個數字」
- **驗收五件事**：畫面、輸出、diff、build、human review
- **不會被 PASS 說服**：reviewer 一直說沒問題時，知道要把 diff 貼給它重查
- **不把「畫面正常」當證據**：知道三種寫法可以做出一模一樣的畫面，其中兩種是壞的
- **說得出「不放行」**：AI 的計畫越界時，能逐條寫出要它拿掉什麼、重出計畫

## 名詞速查表

> **不用背。** 這張表是給你**中途卡住、想不起來某個字是什麼意思時回來查的**。

| 名詞 | 在這門課的意思 | 你要能說出什麼 |
|---|---|---|
| **AGENTS.md** | 這個專案給所有 AI 的工作守則 | AI 動手前應該先讀它 |
| **CLAUDE.md** | 給 Claude Code 的補充守則 | 跟 AGENTS.md 是同一類東西 |
| **Plan Mode** | 讓 AI **只能規劃、不能改檔**的模式 | 這是「先看再放行」的技術保證 |
| **planner** | AI 扮演的第一個角色：只出計畫 | 它這時候改檔就是違規 |
| **人審** | **你**看過計畫、決定放不放行 | 這一步不能給 AI 代勞 |
| **implementer** | AI 扮演的第二個角色：照核准的計畫動手 | 超出計畫就要停下來回報 |
| **reviewer** | AI 扮演的第三個角色：檢查成果 | 但最後拍板的還是你 |
| **PASS / BLOCK** | reviewer 的兩種結論 | 一直 PASS 很可疑，要重查 |
| **A–F 計畫** | planner 要照的固定六段格式 | 格式固定，你才好逐項比對 |
| **允許檔案** | 這堂課准許被改的檔案清單 | 清單外的檔案，AI 想改要先問你 |
| **越界 / scope** | AI 改到清單外的東西 | 發現越界先把範圍拉回來，不要急著修功能 |
| **`C2-HOLE`** | 老師在程式碼裡**故意留白**的地方 | 你的任務就是補這個洞 |
| **action queue** | 備料控制台上「今日優先處理」那一區 | 這堂的成果會出現在這裡 |
| **`orderItems`** | 訂單資料 | 新規則的數字必須從它算出來 |
| **寫死 / 假資料** | 直接打一個數字，不是算出來的 | 畫面對也不合格，因為資料一變就錯 |
| **build** | `npm run build`，把專案打包一次 | 用來確認改完沒把整包弄壞 |
| **diff** | 改之前與改之後的差異（U1 教過） | 這堂用它確認 AI 有沒有越界 |
| **sub-agent** | 把一段 prompt 固化成可重複呼叫的角色 | 加映內容，跳過不影響過關 |
