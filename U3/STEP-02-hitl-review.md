# U3 · STEP 02 ｜ LINE Flex、API、token 與 Human-in-the-loop

> **開始之前**：`STEP-01` 做完後你應該已經讀過 [`API-FLOW.md`](./API-FLOW.md) 的 **§1–2**
>（三個方向、看板怎麼活起來）。還沒讀的話先去讀，只有那兩節，五分鐘。

## 1. 先把資料走到預覽（Button 1-3）

在「LINE 推播中心」先選 **「營運異常」**（紅色那個），依序按下三顆按鈕：

1. **載入資料**——營運異常固定讀 `data-lab/report.json`。
2. **檢查資料合約**——綠色通過代表必要欄位存在，且 `risk_level` 是 `low / medium / high`。資料合約沒過時，後面的 Flex 預覽與推播會被擋下。
3. **生成 Flex 預覽**——你會看到 LINE 卡片樣式，也可以切到 JSON。這就是 payload：前端與後端都要看得懂的結構化資料。

> **讀 [`API-FLOW.md`](./API-FLOW.md) 的 §3**（按下推播之後）。
> 你剛按完前三顆，接下來那張圖講的就是第五顆按下去會發生什麼。

## 1-2. 三種類型都跑一次

剛剛只跑了紅色那一種。**現在把另外兩種也各跑一次**——同樣是那五顆按鈕。

| 類型 | 顏色 | 資料哪裡來 |
|---|---|---|
| 訂單資訊 | 藍 | 看板的即時訂單 |
| 庫存警示 | 琥珀 | 伺服端依**現在的庫存**即時算出來 |
| 營運異常 | 紅 | `data-lab/report.json`（剛剛跑過了） |

跑完之後回答三題：

**① 三種的操作流程一樣嗎？**

<details>
<summary>答案</summary>

**完全一樣。** 都是 `載入 → 檢查合約 → 預覽 → 人工審核 → 推播`。

不一樣的只有**資料從哪裡來**，以及卡片的顏色。

> 這是真實系統的常態：**流程是共用的，資料來源是換的。**
> 你以後接手的系統多半也是這樣——搞懂一條流程，就懂了一整類功能。

</details>

**② 如果你沒有按「開始營業」，哪一種會載不到資料？為什麼？**

<details>
<summary>先自己想，再打開</summary>

**「庫存警示」載不到。**

因為三種的資料來源韌性不一樣：

| 類型 | 沒開店的時候 |
|---|---|
| 訂單資訊 | 退回 `data-lab/orders.json`（有靜態備份） |
| **庫存警示** | **載不到**——它只有即時資料，**沒有靜態備份** |
| 營運異常 | 照常，它本來就是讀靜態檔 |

「現在的庫存還剩多少」這件事**只有正在營業的模擬引擎知道**，
沒有一份預先寫好的檔案能代替它。

**卡住了怎麼辦**：先按「開始營業」讓看板跑起來，再回來載入就有了。

</details>

**③ 為什麼三種要用不同顏色？**

<details>
<summary>答案</summary>

因為收到通知的人**在滑手機**。

他不會逐字讀，他先看到的是顏色。**紅色代表「現在就要處理」，藍色代表「知道一下就好」。**
顏色是在幫收訊息的人分優先順序——這是設計，不是裝飾。</details>

## 2. 人工審核（Button 4）

先不要勾 checkbox。你會看到推播按鈕是暗的。

認真檢查 Flex 卡片後，勾選：

```text
我已人工審核這則通知內容
```

通知不是系統算出來就能送出，而是人審後才送——即使是自動判斷出來的庫存警示也一樣。

## 3. 推播 LINE Flex（Button 5）

按「推播 LINE Flex」。沒設定 token 時，應該看到：

```text
[mock] LINE_REAL_SEND is not 1, no request sent.
```

看到 `[mock]` 就是主線過關，不是手機收到才算過關。

## 4. 用 DevTools 看 API 邊界

按 F12 → Network → 再按一次推播。

你應該看到瀏覽器只打本機 API：

```text
POST /api/send-line-flex
```

前端只送 `template`（訂單資訊時多帶 `orderId`）與 `reviewed`；瀏覽器不會直接打 `api.line.me`，也不會帶 token。token 只在 `line-lab/.env`，真正打 LINE 的是後端。

### ⭐ 再做一件事：證明 token 沒有外洩

在 Network 的**搜尋功能**裡找 `line.me`。

> **你應該什麼都找不到。**
>
> **找不到 ＝ 瀏覽器從頭到尾沒有直接連過 LINE ＝ token 邊界是好的。**
>
> 這是你今天能拿出來最硬的一個驗收證據——而且「**搜不到**」本身就是證據。

> **現在讀 [`API-FLOW.md`](./API-FLOW.md) 的 §4–5**（token 為什麼不會外洩、webhook 是相反方向）。
> 你剛剛親手驗過那條界線了，這時候讀最有感覺。

## 6. 真送是進階，不是主線

有 LINE OA 的同學才做：

1. 複製 `line-lab/.env.example` 成 `line-lab/.env`
2. 填 `LINE_CHANNEL_ACCESS_TOKEN` 與 `LINE_TARGET_ID`
3. 設 `LINE_REAL_SEND=1`
4. 重啟 `npm run dev`
5. 人工審核後再按推播

沒有 LINE OA 完全不影響過關。
